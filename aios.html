Why I built it

AI agents can perform increasingly complex work, but enterprise use introduces a different problem: who has authority, what evidence is required, when must a human intervene, and how can the organization reconstruct what happened afterward?

AIOS treats AI execution as an operational process rather than an unrestricted tool call.

Verified capabilities

Control plane

FastAPI API, browser Command Center, deterministic intent/risk routing, requests, tasks, workflow runs, approvals, alerts, budgets, decisions, outcomes, memory, schedules, and release/governance records.

Runtime governance

Risk-to-approval minimums, evidence/pass/approval stage gates, fail-closed unknown gates, agent risk ceilings, controlled GitHub writes, and human authority ceilings.

Security

Persistent server-side sessions, token rotation/revocation, HttpOnly SameSite cookies, same-origin mutation checks, scoped RBAC, secret redaction, and production configuration validation.

Infrastructure

PostgreSQL, Alembic, non-root production image, Caddy TLS edge, API/worker/scheduler separation, Prometheus, Loki, Grafana, backup verification, and guarded restore.

Durability

Permission-controlled adapters, durable events, retry and dead-letter behavior, execution records, operating briefs, and persistent decisions/outcomes/memory.

Release discipline

Python 3.12/3.13 tests, dependency audit, Bandit, infrastructure validation, PostgreSQL E2E validation, release-readiness checks, exact-SHA merge, protected main, and v1.0.0 release.

Fail-closed gate

The Data Engineering workflow is deliberately advanced before approval and must block. It resumes only after authorized A1 approval.
