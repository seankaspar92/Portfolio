MLB EDGE emphasizes Statcast-oriented ingestion, blocking data-quality controls, research methodology, experimentation, and Baseball Operations-style analytical thinking.

Verified NFL EDGE evidence

Connected decision dashboard

v2.7 exposes a local dashboard that refreshes structured snapshot data and populates Command Center KPIs, opportunity cards, Best Bets, activity, exposure, Model Registry, and Research Lab views.

Transport-only connector

The connector does not calculate picks, change signal state, resize stakes, or promote research models. Production output stays upstream of presentation.

Research firewall

Payloads with an explicitly unlocked research firewall fail validation. Research remains in a separate namespace and cannot create production opportunities through the connector.

Fail-visible fallback

Missing, malformed, invalid, or unreachable live data switches the interface to an explicit DEMO FALLBACK state rather than silently presenting demo data as live.

Feature provenance

Historical features must satisfy the temporal invariant available_at <= prediction_lock_at, with immutable manifest and feature-level provenance records.

Authentic historical prices

Historical evaluation does not invent synthetic -110 odds. Unpriced observations can support football-result diagnostics but are excluded from profit/ROI gates.

Historical replay maturity: the v2.7 chronological/rolling-origin replay foundation is documented as validated in isolation, with tests for prediction-lock timing, provenance, non-overlapping windows, label availability, authentic-price coverage, deterministic identity, and idempotent persistence. Real historical replay data and validated model performance are still explicitly not claimed.

NFL EDGE evidence boundaries

  • Historical provenance contract is implemented as an isolated foundation.
  • Unverified and retrospective-only temporal classes fail predictive eligibility.
  • Feature registration is immutable, version-preserving, and idempotent.
  • Batch provenance registration is atomic when validation fails.
  • Missing historical market prices remain unavailable.
  • ROI-dependent sample gates use authentically priced observations.
Not claimed: real leakage-controlled historical model performance, measured historical price coverage, production model improvement, or a completed real historical replay dataset.

MLB EDGE current boundary

MLB EDGE remains an active local build oriented toward Statcast ingestion, blocking data-quality validation, research methodology, feature development, and Baseball Operations-style analytics.

The portfolio can safely describe the direction and documented working behaviors, but it should not publish model-performance metrics or represent the platform as a released GitHub product until the current repository is published and audited.

Next evidence gate: publish or connect the current MLB EDGE repository, then audit its ingestion code, validation suite, research modules, tests, and reproducible outputs before replacing this boundary statement with exact evidence.
